    02 / ESCRIBÍ Y EJECUTÁ
    Primero la cuenta. Después el botón.
    
            Descargar prueba completa ↓
    
          
    Abrí tests/account-deposit.spec.js, quitá .skip y completá el recorrido.
            El banco debe estar encendido en otra terminal. Reutilizamos lo aprendido para crear una práctica e iniciar sesión por la interfaz.
    
          
    Un page.getByRole('button', { name: 'Depositar', exact: true }) encuentra más de un botón.
            Al hacer click(), Playwright exige un único elemento y rechaza esa ambigüedad.
            exact: true exige el nombre completo; no vuelve único un nombre que está repetido.
    
          
    const cuentaDiaria = page.getByRole('region', {
  name: 'Cuenta ana.diaria', exact: true,
});
await cuentaDiaria.getByRole('button', {
  name: 'Depositar', exact: true,
}).click();
    
          
    cuentaDiaria guarda un localizador, no una captura del elemento. La segunda búsqueda se hace
            solo dentro de esa región. El botón queda identificado por su contexto, aunque cambie el orden de las cuentas.
    
          
    No uses .first() ni .nth(0) para ocultar el problema: elegir una posición no expresa
            en qué cuenta querés depositar. Dentro del diálogo Ingresar fondos ficticios, comprobá que
            Cuenta para depósito tenga el valor técnico ana-main, correspondiente a
            ana.diaria. No cambies el selector para hacer pasar el caso: queremos comprobar que el botón
            abrió el depósito para la cuenta correcta.
    
          
    Ver el test completo, paso a paso
            
    Práctica nueva → acceso → saldos iniciales → botón dentro de la cuenta → diálogo y cuenta seleccionada → importe → saldos finales.
              Los comentarios @snippet identifican fragmentos del material; no son una API de Playwright.

    03 / LEÉ LA EVIDENCIA
    Cambió la cuenta correcta.
    
          
    Ejecutá el caso y abrí el reporte desde la terminal del repo de automatización:
    
          
    npx playwright test account-deposit.spec.js --headed
npm run report
    
          
    El importe que escribís es 100; el saldo se presenta como moneda argentina:
            $ 2.600,00. Comprobá ese texto dentro de ana.diaria, no en toda la página,
            y que ana.ahorro conserve $ 600,00.
    
          
    await expect(cuentaDiaria.getByText('$ 2.600,00', {
  exact: true,
})).toBeVisible();
    
          
    Un aviso de éxito o un clic completado no demuestran que el dinero llegó a la cuenta elegida.
            Verificá primero el nuevo saldo de la cuenta destino y después el saldo de la otra:
            una comprobación que no cambia podría aprobar antes de que termine la operación.
    
          
    Usá aserciones de Playwright con await expect(...). Reintentan la comprobación hasta que se cumple
            o vence el timeout. No agregues waitForTimeout() ni una pausa fija para esperar el depósito.
    
          
    Al completar este caso, la suite acumulada tendrá 6 passed.
            Con el reto resuelto, debería terminar con 7 passed.
