            Debería aparecer el título “Tu sesión de práctica”.

    02 / ESCRIBÍ Y EJECUTÁ
    Una acción, una comprobación.
    
            Descargar prueba completa ↓
    
          
    Abrí tests/create-practice.spec.js en tu repo de tests. Quitá .skip
            y completá el recorrido. El banco debe estar encendido en otra terminal.
    
          
    page.goto('/') abre la bienvenida. getByLabel('Perfil del ejercicio') localiza el selector
            y selectOption('stable') elige su valor técnico. La etiqueta visible de esa opción es
            Estable · comportamiento esperado.
    
          
    click() y fill() son acciones. Aunque los campos ya tengan valores,
            fill() reemplaza su contenido y deja explícitos los datos del caso.
            Las aserciones await expect(...).toBeVisible() comprueban el resultado de las acciones.
    
          
    Ver el test completo, paso a paso
            
    Navegación → perfil estable → crear práctica → título de acceso → credenciales → iniciar sesión → saludo y cuenta.
              Los comentarios @snippet identifican fragmentos del material; no son una API de Playwright.
    
            
    Cargando código…
    
          
    
        
    
        
    
          
    03 / LEÉ LA EVIDENCIA
    El clic no alcanza.
    
          
    Ejecutá la prueba y abrí el reporte desde la terminal del repo de automatización:
    
          
    npx playwright test create-practice.spec.js --headed
npm run report
    
          
    Después de crear la práctica, comprobá el encabezado de nivel 1 “Tu sesión de práctica”.
            Después de iniciar sesión, comprobá el encabezado de nivel 1 “Buen día, Ana.”
            y la región “Cuenta ana.diaria” visibles. Que el clic termine sin error no demuestra que Ana haya entrado.
    
          
    Playwright espera las condiciones necesarias para cada acción y reintenta las aserciones sobre la pantalla
            hasta que se cumplen o vence el timeout. Usá await en cada acción y aserción;
            no agregues pausas fijas ni waitForTimeout().
    
          
    Al completar este test, la suite acumulada tendrá 4 passed. Con el reto resuelto,
            debería terminar con 5 passed.

    04 / TU PRÓXIMO CASO
    Probá una contraseña incorrecta.
    
          
    Escribí un test independiente en tests/create-practice-challenge.spec.js.
            Empezá desde /, elegí el perfil estable y creá una práctica nueva.
            Ingresá el email de Ana y una contraseña incorrecta, por ejemplo ClaveIncorrecta!.
    
          
    Después de pulsar Iniciar sesión, comprobá el mensaje “Email o contraseña incorrectos.”,
            que el título “Tu sesión de práctica” siga visible y que la región “Cuenta ana.diaria”
            no esté visible. Este caso debe poder ejecutarse solo, sin depender de que el test anterior haya iniciado sesión.
    
          
    Necesito una pista
    Repetí el recorrido hasta el formulario dentro del nuevo test.
            Usá fill() para reemplazar la contraseña pública que trae el campo.
            Buscá el mensaje con getByRole('alert') y comprobá su texto con
            toHaveText('Email o contraseña incorrectos.'). Para la cuenta, usá
            getByRole('region', { name: 'Cuenta ana.diaria', exact: true }) con toHaveCount(0):
            no debe existir en la pantalla de acceso. Verificá el error antes de comprobar la ausencia para no aprobar antes de recibir la respuesta.
    
          
    Ya hice mi intento: ver solución
    Extraé la solución en otra carpeta y comparala con tu intento.
            Incluye los tres tests de la clase 01, el acceso correcto y el reto de contraseña incorrecta:
            la suite completa debería mostrar 5 passed.
