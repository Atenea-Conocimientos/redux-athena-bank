01 / TERMINAL DE LA APLICACIÓN

Dejá el banco funcionando.

Necesitás Node.js 24 o superior, Git, un editor y la versión Lab que te entregue el instructor. No es la antigua aplicación Redux con MongoDB. La distribución pública del Lab todavía está pendiente; no clones una versión distinta.

En la raíz de la copia local del Lab:

npm ci
npm run dev

Abrí la comprobación de salud. Debe indicar status: "ok", mode: "local-lab" y realMoney: false. No cierres esa terminal.

02 / TERMINAL DE TUS PRUEBAS

Empezá con una base pequeña.

Extraé el proyecto en una carpeta nueva llamada athena-bank-automation, al lado del banco, no adentro. Abrila en tu editor.

Descargar proyecto inicial (.zip) ↓ 
node --version
git --version
npm ci
npx playwright install chromium
npm test

Resultado esperado: 1 prueba aprobada y 1 omitida. La primera comprueba el servidor. La omitida (skipped) es tu ejercicio, todavía sin implementar: no cuenta como aprobado.

El ZIP incluye package-lock.json, configuración local y README con el paso a paso. No necesitás secretos ni una suscripción para ejecutar las pruebas.

03 / GUARDÁ TU PUNTO DE PARTIDA

Creá tu propio repo en GitHub.

En la carpeta de automatización, iniciá Git y guardá la base:

git init -b main
git add .
git commit -m "chore: preparar laboratorio de automatizacion"

Si Git pide nombre y email, configurá tu identidad para este repositorio. Luego, en GitHub → New repository, creá athena-bank-automation en tu cuenta. Elegí público o privado y dejalo vacío: sin README, licencia ni .gitignore adicionales.

Reemplazá TU_USUARIO por tu usuario real:

git remote add origin https://github.com/TU_USUARIO/athena-bank-automation.git
git push -u origin main
git switch -c clase/01-primera-prueba

Autenticate con el flujo normal de GitHub. No escribas claves en el código, commits o URL. El proyecto ya ignora dependencias, reportes, sesiones y archivos .env.

04 / UNA CLASE, UN CAMBIO CONCRETO

Intentá. Comprobá. Compará.

  1. Inicio. Leé el escenario y los resultados esperados; reproducilo manualmente.
  2. Tu rama. En tests/first-test.spec.js, quitá .skip y escribí las aserciones. Corré npm run test:headed para ver el navegador.
  3. Tu evidencia. Guardá el intento y el resultado. Ante un fallo, revisá el reporte y el trace antes de agregar una espera fija.
  4. Solución. Compará con el test de referencia de la lección. Extraé el ZIP solución en otra carpeta para conservar tu trabajo.
git add tests/first-test.spec.js
git commit -m "test: comprobar bienvenida del banco"
git push -u origin clase/01-primera-prueba

Podés abrir un PR de esa rama hacia main en tu propio repositorio. No necesitás modificar ni enviar PR a la aplicación bancaria.

Cómo organizaremos el curso: cada clase tendrá clase-NN-inicio y clase-NN-solucion como referencias del instructor. Tu rama es tu espacio de trabajo; no cambies de rama con cambios sin guardar. Las clases van sumando lo aprendido.

Disponible ahora: los ZIP acumulativos de inicio y solución de las clases 01 a 06. Cada clase ofrece sus descargas; no necesitás ramas remotas del instructor para seguir el piloto.

Si algo no arranca
  • ECONNREFUSED: revisá la terminal del banco y el puerto 4177.
  • Chromium no instalado: corré npx playwright install chromium en el proyecto de tests.
  • Node incompatible: instalá Node.js 24+ y reabrí tu terminal.
  • Test omitido: es el ejercicio inicial; falta implementarlo y quitar .skip.
  • No te pedirán claves de QA o producción: las prácticas usan datos ficticios y la URL está restringida a localhost.

Fuentes: instalación de Playwright, aserciones y preparación por API.
